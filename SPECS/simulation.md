# Simulation Specification

## Overview
The simulation runs traffic scenarios to evaluate dispatch performance. It generates synthetic requests following realistic patterns, feeds them to the brain, and collects metrics the brain already tracks (wait time, journey time).

## Event Types

### Request Arrival
- A passenger request appears at a floor.
- Contains: originFloor, destinationFloor, boardingCount, timestamp.
- Generated by the traffic scenario.

### Car Stop Complete
- A car finishes a stop (doors closed, ready to move).
- Triggers the car to pull its next destination.
- This is when the brain marks parties as BOARDED.

### Car Arrival
- A car reaches a floor.
- Triggers optional status report to brain.
- Doors open → dwell → close.

## Traffic Scenarios

A full day cycle runs these scenarios sequentially:

### 1. Up-Peak (Morning)
- Duration: 30 minutes
- Pattern: People arrive at lobby (floor 1) and go UP to offices.
- Origin: 90% from floor 1, 10% from other entry floors.
- Destination: Uniform across floors 2–40.
- Arrival rate: ~15 requests/minute total.
- Party size: 1–3, average 1.5.

### 2. Midday / Lunch
- Duration: 60 minutes
- Pattern: Two-way traffic, balanced up and down.
- Origin/Destination: Uniform across all floors.
- Arrival rate: ~8 requests/minute total.
- Party size: 1–2, average 1.3.

### 3. Down-Peak (Evening)
- Duration: 30 minutes
- Pattern: People leave from offices going DOWN to lobby.
- Origin: Uniform across floors 2–40.
- Destination: 90% floor 1, 10% other exits.
- Arrival rate: ~15 requests/minute total.
- Party size: 1–3, average 1.5.

### 4. Off-Peak
- Duration: Remaining time (night)
- Pattern: Low random traffic.
- Origin/Destination: Uniform across all floors.
- Arrival rate: ~1 request/minute total.
- Party size: 1, average 1.0.

---

## Traffic Generation

Use Non-Homogeneous Poisson Process (NHPP) with thinning:
- Define a lambda(t) curve for each scenario.
- Thinning algorithm: sample from exponential distribution with lambda_max, accept with probability lambda(t)/lambda_max.

**Implementation:**
- Apache Commons Math for ExponentialDistribution and PoissonDistribution.
- Each scenario defines its own lambda(t) function (can be constant per scenario for v1).

## Running the Simulation

1. Start brain server.
2. Initialize traffic generator with scenario params.
3. For each scenario in day cycle:
   - Generate requests at the defined rate.
   - Send each to the brain via POST /api/requests.
   - Record request timestamp.
4. Let simulation run to completion.
5. Query brain for collected metrics (wait times, journey times, max wait).

---

## Metrics Collected (from brain)

- **Average waiting time**: request → pickup
- **Average journey time**: request → delivery
- **90th percentile wait**: tail control
- **Max wait**: worst case
- **Throughput**: requests delivered per minute

These are computed by the brain from requestId + timestamps. The simulation just runs the scenarios and reads the results.
